Overall, the system is an **early adaptive lesson platform**. It already does more than deliver quizzes: learner evidence and due state affect future work, and a source store supports authorship. Its operational strength is scoped evidence and durable lesson delivery. A reusable curriculum library, independent transfer measures, mastery calibration and a proven tutoring path are still missing. The knowledge subsystem is a source library, not the learner's memory.

## Exercise engine

All current baseline input types are listed below. Numeric and photo are capabilities of an input and need not be counted as separate learning activities. Keys and rubrics are authored with the exercise and validated by the server before use.

| Interaction | Implemented behavior | Evaluation and boundary |
|---|---|---|
| `choice` | Checkbox set supports one or several correct options. There is one key type and no separate radio-only answer contract. Can represent recognition, discrimination, association or applied interpretation depending on prompt. | Exact set comparison, with no partial credit in the baseline. Wrong choices can carry authored error labels. |
| `short` | Single-line text, word/formula recall and numeric answers. Numeric parser handles supported numbers/fractions, tolerance and optional units. | Text normalization, explicit accepted variants and case option, numeric comparison, or rubric. Omitted units can pass the existing numeric evaluator. That matters where units are the objective. No symbolic algebra/CAS or general mathematical equivalence. |
| `long` | Multi-line explanation, written production, problem reasoning; optional/required photo where configured. | Rubric and human/eligible AI path. No universal semantic equivalence checker independent of the rubric. |
| `cloze` | Inline missing fields between authored text fragments. | Per-blank text comparison and partial credit. Can test reconstruction and recall. |
| `match` | Association of prompt-side IDs to response-side IDs, using structured controls. | Deterministic correct pairs and partial credit. |
| `order` | Reorder a sequence of supplied steps. | Position-based partial scoring. Author must choose a defensible order; equivalent orders are not encoded. |
| `label` | Fill text fields for marks on a supported image. Reading pages also render static figures. Photos attach learner work. | Per-label text compare and partial credit. No arbitrary image hot spots, sketch canvas, or generalized visual inference engine. |
| `table` | Fill a grid with typed cells. | Per-cell text/numeric key and partial credit. Useful for data interpretation and science. No spreadsheet or simulation engine. |
| `code` | Source editor with language, starter, line feedback and an authored rubric; code can be displayed with notes in teaching sections. | Rubric feedback only. No compiler, runtime, executable tests, or proof that submitted code satisfies requirements. |

Evidence: [item UI](../../app/hub/lesson-v2/item-card.tsx#L83), [structured controls](../../app/hub/lesson-v2/inputs/structured.tsx), [code input](../../app/hub/lesson-v2/inputs/code.tsx#L16), [v3 item types](../../lib/contracts/lesson-package-v3.ts#L38), [deterministic and partial grading](../../lib/evidence/autograde.ts#L13), [numeric parsing](../../lib/lesson-v2/numeric.ts), [validation](../../lib/lesson-v2/validate.ts), [upload path](../../lib/uploads/service.ts).

**Additional format maturity.** Audio/listening is absent from the baseline. Integration has DE/ZH rendered audio assets via system TTS, playback UI, dictation key and closed/open response options. The L2/L5 QA combines local media and simulated or separate components. L3 topic code records completed plays, assistance and stimulus, distinguishes text replacement, and requires independent audio evidence on two Berlin days for secure listening. Own-voice speech recording, recognition and pronunciation scoring remain absent. No interactive simulations are implemented in the inspected baseline. T1 offers fake/queued tutoring on a topic branch, and its status lists real relay/inference and support tracking as dependencies. ### Learning objective versus interaction

| Objective requested | Current representation | Evidence caveat |
|---|---|---|
| Recall | `recall`; short, cloze or closed prompt | Recognition in a choice item can be easier than unaided recall. |
| Discrimination | `recognize`; select a suitable example, suspect inference or error | Distractor rationale needs explicit authoring. |
| Association | Match, label or choice; generally `recognize` or `apply` | Match expresses interaction. There is no dedicated association activity label. |
| Reconstruction | `transform`; cloze, ordering, sentence or derivation rewrite | Template replay may inflate apparent reconstruction. |
| Interpretation | `investigate`, `apply` or `explain`; charts, tables, figures and case evidence | Depends on fit of the prompt/key and live source evidence. |
| Explanation | `explain`; long or rubric-enabled short | Open reasoning requires adjudication or reliable rubric calibration. |
| Application | `apply`; numeric, structured or rubric questions in a scenario | A correct answer can still be guessed or reflect near transfer. |
| Error detection and repair | `correct`; detect via choice, repair via typed/structured input | Baseline can label repeated errors. It cannot reliably disambiguate a slip, prompt ambiguity and actual misconception. |
| Production | `create`; writing, code, photo evidence, report | No execution or speech performance scoring. |

The code already separates activity, response format, difficulty, skills and evaluation to a useful degree. Validation permits combinations while enforcing format-specific attributes. The same skill can be measured by several different inputs. Keep these dimensions explicit. Make the validator, serializer, renderer and grading dispatch agree on each supported input through shared contract tests. The per-notebook item allowlist and single persisted format in integration are the existing implementation of this direction. Normalize text/numeric/structured keys through shared evaluators and keep distinct accessible controls for cloze, matching, ordering, labels and tables. Add stable objective refs, evaluator IDs and evidence context only when used by two practical tasks. Preserve legacy parsing on read during migration. A universal plug-in marketplace or arbitrary combinations of all possible input/evaluation modes would add complexity before users demonstrate the need. [Item activity schema](../../lib/contracts/lesson-package-v2.ts#L13), [integration item policy](https://github.com/unhuman1289/learning-hub/blob/2a02136/lib/subjects/item-kinds.ts), [V3 readback](https://github.com/unhuman1289/learning-hub/blob/2a02136/docs/plan/status/V3.md).

## Learning loop

| Stage | Verified mechanism | Evidence gap and proposed owner |
|---|---|---|
| **Discover** | Opening brief, diagnostics and placement, skill sheet, sourced readings, notebook roadmap, discovery/extra request. A diagnostic can create initial skill evidence. | Ground common diagnoses in a reviewed short diagnostic. Use AI for bounded examples and variable case drafts. |
| **Recall** | Retrieval/review stages and closed/unassisted work. Hints or full reveals record support and affect strength. | Preserve support. Add cold retrieval items for a same-skill pair and retain the item/version for longitudinal comparison. Server owns scoring where answers are known. |
| **Repair** | Instant deterministic comparison, targeted feedback/rubric, ability to retry or dispute. Authored choice labels/AI diagnoses feed pattern grouping. `knowledge`, `application`, `slip`, `reading`, `unknown` are distinguished. Labels accumulate across days before confirmation, and later clean independent performances can resolve them. | A label is a hypothesis. Use a discriminating corrective item to test the cause before declaring it. Keep diagnosis reviewable and use AI for drafts and uncertain feedback. |
| **Reapplication** | Confirmed errors/weak prerequisites and current roadmap drive selection. Qwen is constrained by chosen skill and novelty checks when writing an exercise. A redesigned item can retry a concept. | Dedup checks prompts, not semantic context distance. Tag a scenario/context family and verify a generated or curated item varies it. Select targets deterministically. |
| **Transfer** | `apply`, `transform`, `create`, `investigate` activities with first-attempt unassisted evidence drive roadmap progression. Challenge uses 5–6 items, minimum 80% independent correctness, coverage of required skills. Roadmap and mastery use evidence beyond lesson completion. | Transfer here is an item-activity proxy. Novel context has no independently validated measure and H9 cross-notebook concept work is planned. Measure a held-out scenario with unassisted application before advancing. |
| **Review** | Rule-owned intervals 1/3/7/14/30/60 days, normally initialize at 3 after adequate evidence, reset after failure, require different days for progression and lack of support for strongest evidence. Mastery tracks knowledge, recognition, application and delayed retention. Bounded proposals can adjust review within rules. | Separate due date and actual completion. Observe due-review uptake and 7/14-day outcomes by skill. Start with this scheduler; tune using evidence before adopting another algorithm. |

The server can already vary difficulty by bounded roadmap band and scaffolding, retain history, and distinguish supported immediate recall from independent delayed application in code. It has no validated measurement of durable learning across domains. Transfer scoring currently risks overstating repeated contexts and model grading errors. Preserve the loop, extend evidence and evaluation, then simplify parallel scheduling or representations where tests demonstrate equivalent behavior.
