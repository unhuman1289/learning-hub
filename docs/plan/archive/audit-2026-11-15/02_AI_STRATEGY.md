# AI strategy

Provider documentation checked 15 November 2026. Current implementation refers to the production-equivalent source tree in [Current state](01_CURRENT_STATE.md). Prices and comparisons describe options. The 14 October owner decision excludes paid OpenAI/Anthropic model API dependencies and keys from the Hub. Introducing any new external inference path calls for a separate owner decision, a defined data boundary, and measured benefit.

## What runs today

The Hub Worker schedules, leases, builds context, validates and applies results. The runnable home runner constructs only Qwen at startup, using a configurable LM Studio loopback URL and default model `qwen/qwen3.6-35b-a3b`. The repository includes Codex and Claude adapters, evaluation tools, prompts and a retained Sites bridge. Those files alone do not establish enabled paths. The current production reference accepts Knowledge-only direct MCP. Non-production direct MCP planning and adult Deutsch text assessment are separately gated. ### Timing, costs and quality evidence

- Historical Qwen Deutsch set (4 authored submissions, 16 answers) reported 20.9s mean, ~2.6k input/~1k output, 4/4 JSON and 14/16 grade agreement. Codex `gpt-6.1-sol` reported 31.5s mean, 4/4 JSON and 15/16 agreement, with usage unmetered. A local end-to-end accepted grade took 11s. In the expanded 32-answer draft-key sample Qwen had 8/8 JSON, 23.9s mean, 24–26/32 grade agreement, and a non-verbatim evidence quote. These are small authored samples, with the expanded result below the plan's 90% bar. [Validation and evals](../VALIDATION.md#L217), [eval runner](../../scripts/eval-local-grader.mjs), [fixtures](../../fixtures/eval/assess).
- Integration V3 reports 15/15 generated lessons saved and read back on local QA. First-pass results were Deutsch 4/5, Rust 5/5 and Maths 0/5. All six first failures needed repair. A later numeric-parser fix yielded 2/2 first-pass Maths saves in a follow-up. The samples support narrowing schemas and replaying failures. Content quality, retained learning and general first-pass rates remain open. [V3 gate](https://github.com/unhuman1289/learning-hub/blob/2a02136/docs/plan/status/V3.md).
- A lease snapshot and hash bind outputs to context. The runner compacts its plan payload toward 24 KB, uses Zod/dry-run/repair and reads the same job on an uncertain save. LM Studio reports tokens where available and elapsed call time, with a ten-minute request timeout and a 12,000-token output limit. The 24 KB target governs compacted plan context, apart from the system prompt, schema and any images. Call failures and timeouts at lease boundaries can leave work waiting until recovery; app state must not imply that feedback is ready. In database cost calculation an unknown model rate is unknown, and final usage commonly covers the accepted generation round only. Today’s offline message is part of the product contract. Measure queue and end-to-end latency separately. ### Sign in with ChatGPT decision for this hosted Hub

- **Website identity** is a supported technical pattern with approved access. The backend uses OAuth authorization code with PKCE and OIDC, exact registered callback URLs per environment, verified state, nonce, issuer, audience, signature and subject, and an app-issued session. Request a client ID through OpenAI's limited partner process. Production would require approval, production callback registration and separately confirmed plan-use entitlement. The partner directory contained no Learning Hub listing, and the repository supplies no evidence of approval/client registration. Household profile ownership and guardian roles would still need explicit account linking. [Website OAuth](https://developers.openai.com/siwc/website), [client ID request](https://developers.openai.com/siwc/request-client-id), [partner directory](https://learn.chatgpt.com/docs/sign-in-with-chatgpt).
- **Plan sharing** is independently consented. The current Help Center lists eligible Go/Plus/Pro/Business participating commercial experiences, subject to app availability, workspace admin/seat/credit rules and user caps. Requests use included Work/Codex allowance or explicitly allowed credits. Identity alone grants neither plan use nor ChatGPT memory/API credentials. Ordinary project API use still has separate billing. A separate claimable Pro/Business API credit offer can fund an eligible linked API organization and excludes Plus. It does not grant SIWC rights or remove this project’s API-policy gate. [API credits eligibility](https://help.openai.com/en/articles/20001626-api-credits-benefit-for-eligible-chatgpt-subscriptions), [API billing](https://help.openai.com/en/articles/9039756-managing-billing-for-chatgpt-and-the-api-platform), [plan use and consent](https://help.openai.com/en/articles/20001542-using-your-chatgpt-plan-in-other-apps-and-sites).
- **The open-source/local route** supports eligible user-controlled runtimes. The documented flow includes loopback registration, PKCE, stable host identity, an issued client ID and separate plan-use scope, local token storage and supported Responses features. Terms require the user's local or exclusively controlled remote runtime, the authenticated user's requests, explicit background consent, no pooled or transferred usage, and prohibit sending personal information of children under 13 or the applicable digital-consent age. Publishing source or putting a worker behind a family gate establishes none of these for a shared hosted runtime. An OpenAI-approved partner arrangement would need written confirmation of the precise hosted topology and rights before engineering spend. [Open-source flow](https://developers.openai.com/siwc/token-sharing-open-source), [supported errors and permission](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery), [SIWC Terms](https://openai.com/policies/sign-in-with-chatgpt-terms/), [commercial interest form](https://openai.com/form/sign-in-with-chatgpt-interest/).

**Recommendation:** defer identity-only SIWC and omit user-subscription inference from the hosted roadmap. Existing MCP is OAuth in the opposite direction (Hub authorizes ChatGPT to call scoped tools) and already fits public-source maintenance. Keep each user's subscription separate, and use only the vendor's supported authorized runtime. The presence of CLI adapters is insufficient evidence for processing another learner's content under a shared subscription.

## Monthly inference model

Assumptions based on a completed-study cadence, not billing or production logs. Numbers count AI plan jobs, AI-graded submissions (multiple open answers may share a job) and rechecks. Closed submissions add zero model calls. Reuse of reviewed items can reduce the number of plan jobs. All scenarios add 20% token headroom for retries/repair and bill uncached tokens. Reasoning tokens must be included in actual usage; images/audio, source search, tutoring, special tiers, taxes, human review and D1/R2/Worker hosting are excluded. Planning and recheck sizes are assumptions. The assessment size is rounded up from the historical Qwen sample.

| Workload per active learner per 30 days | Plan at 8k in / 2k out | Assess at 3k / 1k | Recheck at 4k / 1k | Base input / output |
|---|---:|---:|---:|---:|
| Light · reusable lessons, weekly personalized set | 4 | 12 | 1 | 72k / 21k |
| Core · three personalized sets per week and frequent open work | 12 | 32 | 2 | 200k / 58k |
| Intensive · near-daily personalized sets, two open submissions on study days | 24 | 64 | 4 | 400k / 116k |

Values are monthly USD, **light / core / intensive**. DeepSeek uses conservative peak rates throughout (off-peak-only is half). Workers AI uses billed neurons after the free daily allocation, assuming even use across 30 UTC days. Free tier blocks overage days. Add the Workers Paid base fee (currently $5/month per account) if required and if it is not already paid. Nightly peaks can consume daily allocation unevenly. API formula: 1.2 × learner count × (input millions × input rate + output millions × output rate). Workers AI formula: at even load, subtract 300,000 neurons from total monthly neurons (4,625 per million input and 30,475 per million output), then multiply positive remainder by $0.011/1,000. A hypothetical 90% Luna / 10% Sol core mix by **billable token volume** costs ~$0.17 per learner/month (about $171 at 1,000). This is a budgeting illustration, pending the owner's policy change and actual evals.

**Local sensitivity:** all five learner scales have $0 metered inference fees. Core scenario gives 46 base model jobs per learner. At an illustrative 60s mean/job and 20% extra attempts, 1, 5, 20, 100 and 1,000 learners consume about 0.92, 4.6, 18.4, 92 and 920 sequential runner hours/month. The last figure exceeds 720 hours in 30 days even with continuous service. At 25 W incremental load and $0.30/kWh, active inference alone is about $0.01, $0.03, $0.14, $0.69 and $6.90 respectively, across the required machines. A machine kept online at 15 W baseline costs another $3.24/month at that illustrative tariff. Hardware, supervision, overnight queue burst and repair tail dominate the economics of the home runner. These watts, tariff and blended time are assumptions; measure on the actual Mac.

## Recommendation by task

- **Deterministic:** closed answers, text/units with explicit normalization contracts, assignment eligibility, completion, review dates, support capture, quota and access, independent mastery bounds, source version validation.
- **Local Qwen:** asynchronous personal lesson drafting and low-stakes open work during the family pilot, with strict JSON/domain validation and human-correctable feedback. Keep hosted inference independent of the authority to write.
- **Small managed model, if approved and justified:** public/synthetic lesson variants, extraction and other repetitive low-risk work where a small blinded eval shows an advantage. Compare Workers AI and economical APIs on the same cases, accounting for paid base, privacy and latency.
- **Stronger model or human:** difficult open feedback, disputed answers and original complex cases. Escalate uncertainty and disagreements to a reviewer. Use clinician-authored keys and synthetic cases for advanced cardiology. Expert adjudication remains the authoritative outcome.
- **Measure before routing:** by job purpose/provider/model/prompt version record queue age, total elapsed, attempts, per-round tokens, structured validation, successful saved lessons/grades, actual adjudicated agreement and false-negative evidence. Report p50/p95, mobile success and price per accepted result. Use the existing job contracts as the adapter boundary. Add a second adapter only after it passes the same learning and data gates.
