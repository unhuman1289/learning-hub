# Prioritized roadmap

This is a proposed decision and verification sequence. Follow [PLAN §6 and gates A–D](../plan/PLAN.md#6-thứ-tự-pr) for the existing release work. Reconcile it with the merged [HUB-NEXT plan](https://github.com/unhuman1289/learning-hub/blob/ffb6519/docs/plan/HUB-NEXT.md), its [integration status](https://github.com/unhuman1289/learning-hub/blob/2a02136/docs/plan/HUB-NEXT-STATUS.md), and the [L/G/T/K plan](https://github.com/unhuman1289/learning-hub/blob/2a02136/docs/plan/LGTK.md) before starting implementation. Estimates are engineer-days for a developer familiar with the repo. Pilot duration is elapsed time. Thresholds below are proposals unless explicitly attributed to an existing plan.

## P3 · Deferred choices

- Hosted Sign in with ChatGPT inference requires explicit official approval for this deployment and its runtime/consent model, plus an account-linking benefit. A prospective integration is outside the pilot. [AI strategy](02_AI_STRATEGY.md#sign-in-with-chatgpt-decision-for-this-hosted-hub).
- Defer a universal engine, cross-subject graph, arbitrary code execution, speech grading, marketplace and production tutor until a measured pedagogical need and a narrowly scoped test justify them. Existing T1 demo status is not live tutoring. H9 remains subject to two stable notebooks, concept evidence and Gate D.
- Use Sites selectively for public/synthetic prototypes in a separate authorized task. Production remains Cloudflare per the existing cutover decision.

## Release and migration invariants

1. Freeze read-only before-images and take a private snapshot with a tested restore. Compare old and new readbacks by IDs, counts, grade pointers, authorizations and due-day rules. Preserve IDs and historical evidence and validate R2/auth separately. Stop before destructive steps if any proof fails.
2. Prefer additive columns/anchors and compatibility reads. Pin lesson, rubric and evaluator revisions for new experiments. Backfill derived state only after a deterministic replay diff explains every intended change. Do not replace unfinished lessons or create synthetic completion.
3. Respect daily primary eligibility (pre-midnight completion in Europe/Berlin) and distinct extras. Test DST, race and undo. Require same-job readback after uncertain writes and use lease/result replay protection.
4. Finish local → staging → authorized production through existing gates, pin runner compatibility and keep environment credentials separate. Record separate evidence of service health, actual saved results, and learner outcomes.
5. Publish decisions in the existing plan/status files when authorized. Preserve repository instructions and prioritize the next gate over starting another broad redesign.

The first decision is to select a single staging revision for P0 readback, confirm data preservation and complete the adult/Maths acceptance path. The roadmap relies on evidence from that revision before treating newer integration work as release-ready.
